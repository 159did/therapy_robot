# 开发规矩

## 范围与工作树

- 主仓库：/home/zzq/PTR/therapy_robot。
- 主分支不得直接承载未审查实验；新任务使用独立分支和 worktree。
- 不覆盖其他人的未提交修改，不使用 git reset --hard，不强推共享分支。
- 提交前记录基线、分支、worktree、HEAD、测试和变更文件。
- 以后正式说明只更新 docs/project/；旧目录仅作为保留的任务卡、证据和历史索引。

## 硬件边界

- 未经明确批准，不访问真实 Nano、实体串口、D405/RealSense，不启动硬件模式，不部署、不使能、不回零、不置零、不点动、不移动。
- 仿真通过不等于 ARM64、Nano、实体硬件或 H1 通过。
- 不生成或发送串口 payload、原生电机 setpoint、正式 K0-K4 目标。
- 不修改正式标定、相机外参、offset、软限位或碰撞边界。
- 任何安全状态不明、反馈丢失、急停/看门狗/限位/碰撞/抱闸异常均为 NO-GO。

## 证据规矩

每项代码修改必须记录：修改提交、具体文件、函数/结构体/API、行为变化、测试方式、Shared Memory 影响、实体电机影响、Nano 是否同步及对应 SHA-256。没有证据的字段写 UNKNOWN 或 NOT_VERIFIED，不能推断为 PASS。

H1 当前是轻量只读状态展示，机器可读值为 `H1_BASIC_READONLY`，只报告设备名和 K0-K4 在线/故障/使能状态。不得把 H1 状态解释为实体运动授权。

当前统一规则：H1 已 `PASS`；实体运动授权是独立状态，当前 `execution_allowed=false`、`entity_action_authorized=false`、`entity_motion_authorized=false`。
