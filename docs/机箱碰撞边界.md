## 安全模型

机械臂使用胶囊体近似：

- K0 升降立柱；
- 大臂；
- K2 关节轴；
- 肘部下沉段；
- K3 关节轴；
- 小臂；
- K4 关节轴；
- 腕部；
- 按摩工具。

机箱实体使用轴对齐长方体近似。开槽面板应拆成槽口上、下、左、右四个或更多长方体，槽口本身不填写障碍物。

碰撞判断使用：

```text
连杆实际半径 + 配置的安全余量
```

检查包括目标姿态和当前位置到目标姿态的关节插值路径。实体运行时还会持续检查实际反馈姿态；实际姿态进入配置障碍物时锁存急停并下电。

## 坐标约定

配置统一使用机器人基座坐标系和米：

- 原点建议设在 K0 中心线投影到机箱基准底面的位置；
- `+Z` 向上；
- 当前运动学中 K1=0 时大臂朝 `+Y`；
- `+X` 为左右方向。

如果实物安装方向不同，必须先建立机箱测量坐标到机器人基座坐标的变换，不能直接套用照片尺寸。

## 配置文件

源码配置：

```text
config/enclosure-collision.csv
```

格式：

```csv
setting,enabled,false
setting,safety_margin_m,0.020
setting,lift_step_m,0.005
setting,joint_step_deg,1.0
setting,upper_arm_radius_m,0.060
box,面板名称,x_min,x_max,y_min,y_max,z_min,z_max
```

所有长度使用米。没有完成测量时不得把 `enabled` 改为 `true`。

实体配置还包含：

```text
THERAPY_ROBOT_COLLISION_CONFIG=/home/jetsonorin/Documents/therapy_robot/config/enclosure-collision.csv
THERAPY_ROBOT_COLLISION_REQUIRED=0
```

完成测量、仿真和低速验证后才把 `REQUIRED` 改成 `1`。此时文件缺失、格式错误、`enabled=false` 或没有障碍物都会阻止进程启动。

碰撞模型使用机器人基座中的绝对关节姿态，因此实体模式启用碰撞边界前还必须完成五轴绝对零偏标定。`hardware_relative` 把启动姿态当临时零位，不能可靠映射到机箱坐标；程序会拒绝在这种模式下启用机箱碰撞边界。

## 防绕过位置

碰撞检查不只放在网页：

1. `/api/ik/check` 同时返回 IK 和碰撞路径结果；
2. 末端目标写入共享状态前再次检查；
3. 原始 K0～K4 目标写入前检查；
4. `main_control` 在 IK 解转换为轴目标前检查；
5. `main_motor` 在发送真实电机目标前做最终检查；
6. 实体反馈轮询时监控当前姿态。

网页、脚本或共享内存中的单一入口不能代替电机层最终保护。


## 当前限制

- 实体配置保持 `enabled=false`，当前没有有效障碍物盒；
- Nano 仍是没有机箱碰撞逻辑的旧部署；
- 限位块宽度、厚度和小臂外壳包络尚未实测；
- 机箱坐标到机器人基坐标的变换尚未标定；
- `2 mm` 只是不含误差预算的名义间隙，不能当作安全余量；
- 轴对齐长方体是保守近似，不表达斜面和圆角；
- 路径检查按关节插值采样，当前电机没有完整的同步轨迹控制；
- 软件轮询和软件急停不能代替硬接线物理急停；
- 停止距离、结构弹性、线缆摆动和零位误差必须计入安全余量；
- 当前模块是工程保护，不是安全认证系统；
- 自动绕行尚未加入，当前检测到碰撞会拒绝命令，不会自行寻找另一条路。
