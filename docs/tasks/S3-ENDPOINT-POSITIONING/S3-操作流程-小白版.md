# S3 末端定位离线操作流程（小白版）

本文用于第一次运行 PTR 的人。照着顺序执行，可以完成一次 S3 末端定位离线检查。

S3 会检查：目标是否能通过逆运动学求解、关节是否越过软限位、路径是否碰撞、实际反馈误差是否合格。它是软件离线检查，不会让真实机械臂运动。

## 0. 先确认安全边界

- 本流程只在 `zzqVM`（x86_64 虚拟机）执行。
- 不连接 Nano，不打开实体串口，不访问 D405。
- 不启动 `main_motor`，不使能、回零、置零、松闸或发送目标命令。
- S3 的 `PASS` 只表示软件输入通过模型检查，不表示实体机械臂已经通过真实定位测试。

## 1. 进入项目并确认版本

在 zzqVM 终端执行：

```bash
cd /home/zzq/PTR/therapy_robot
git status --short --branch
git log -1 --oneline
```

应看到分支是 `main`，并且最新提交为 `46c24f7`（或之后的提交）。如果工作区有自己不认识的修改，不要提交、删除或覆盖，先保存现场。

## 2. 编译 S3

第一次运行或源码更新后执行：

```bash
cmake -S . -B build/s3-user -DBUILD_TESTING=ON -DCMAKE_BUILD_TYPE=RelWithDebInfo
cmake --build build/s3-user --parallel 2
```

这是纯软件编译，不会访问硬件。看到下面两个目标表示 S3 程序已生成：

```text
Built target endpoint_positioning_report
Built target test_endpoint_reachability_matrix
```

编译失败时不要启动硬件程序，也不要把旧二进制复制到 Nano；保存最后 30 行错误信息即可。

## 3. 运行完整离线测试

```bash
ctest --test-dir build/s3-user --output-on-failure -j2
```

当前集成版本的预期结果是：

```text
26/26 tests passed, 0 tests failed
```

不是 `26/26` 时，不要把结果称为 S3 通过，先看失败测试名和错误信息。测试包括运动学、碰撞、安全门、API、末端定位、CLI、14 点可达性矩阵和 D405 软件契约检查；D405 契约检查不会启动相机。

## 4. 运行 14 点可达性检查

这是最适合第一次操作的检查：它会打印每个目标点是否可达以及拒绝原因。

```bash
build/s3-user/test_endpoint_reachability_matrix config/enclosure-collision.csv
```

保存输出（推荐）：

```bash
mkdir -p /tmp/s3-user-results
build/s3-user/test_endpoint_reachability_matrix config/enclosure-collision.csv \
  | tee /tmp/s3-user-results/reachability-matrix.txt
```

最后一行应类似：

```text
SUMMARY total=14 reachable=11 rejected=3 serial_accessed=false d405_accessed=false motor_command_generated=false
```

这里的 3 个拒绝是故意设计的安全测试，不是故障：2 个点会进入机箱碰撞区域，1 个点超出 IK 工作空间。看到 `reachable=false` 时要看 `reason`，不能只看真假。

## 5. 运行末端定位报告

可达性矩阵回答“目标能不能走到”；报告工具还回答“实际到位误差是否合格”。先使用项目自带的合成样例：

```bash
mkdir -p /tmp/s3-user-results
build/s3-user/endpoint_positioning_report \
  --input tests/fixtures/endpoint_positioning/offline_measurements.csv \
  --collision-config config/enclosure-collision.csv \
  --json /tmp/s3-user-results/endpoint-report.json \
  --csv /tmp/s3-user-results/endpoint-results.csv
```

正常结果是返回码 `0`，JSON 中 `status` 为 `PASS`，`accepted_samples` 为 6，`rejected_samples` 为 0。查看 JSON：

```bash
python3 -m json.tool /tmp/s3-user-results/endpoint-report.json
```

## 6. 看懂阈值和结果

默认阈值：

```text
位置误差：0.001 m = 1 mm
姿态误差：0.017453292519943295 rad ≈ 1°
```

一个样本只有在以下条件全部满足时才会 `accepted=true`：起点软限位通过、目标 IK 成功、目标软限位通过、碰撞配置存在并启用、起点不碰撞、整段路径不碰撞、实际反馈软限位和碰撞检查通过、位置误差不超过 1 mm、姿态误差不超过约 1°。

返回码含义：

```text
0：全部样本通过
1：有样本拒绝、碰撞配置错误或输出失败
2：参数、CSV 或阈值输入错误
```

常见拒绝原因：

```text
position_error_exceeds_tolerance       位置误差超限
orientation_error_exceeds_tolerance    姿态误差超限
endpoint path rejected                  路径碰撞
IK rejected target                     超出工作空间或姿态不可解
IK target exceeds K* soft limit        目标关节超出软限位
```

不要为了让结果变成 PASS 而调大阈值、关闭碰撞配置或修改软限位。

## 7. 使用自己的 CSV（可选）

先把自带样例跑通，再替换输入。CSV 必须使用下面的 18 列表头，顺序不能改：

```text
sample_id,side,source_k0_m,source_k1_rad,source_k2_rad,source_k3_rad,source_k4_rad,target_x_m,target_y_m,target_z_m,target_rx_rad,target_ry_rad,target_rz_rad,actual_k0_m,actual_k1_rad,actual_k2_rad,actual_k3_rad,actual_k4_rad
```

单位：K0 和目标 `x/y/z` 用米；K1-K4 和目标 `rx/ry/rz` 用弧度。 `source_*` 是起点五轴反馈，`target_*` 是目标末端位姿，`actual_*` 是到位后的五轴反馈。

例如 313.1 mm 的 K0 必须写成 `0.3131`，不能直接写 `313.1`。运行自己的文件：

```bash
build/s3-user/endpoint_positioning_report \
  --input /绝对路径/你的数据.csv \
  --collision-config config/enclosure-collision.csv \
  --json /tmp/s3-user-results/my-report.json \
  --csv /tmp/s3-user-results/my-results.csv
```

实体采集的数据还必须另外保存采集时间、Nano 软件版本、设备身份、单位和反馈年龄；S3 不会自动补造这些实体证据。

## 8. 运行重复定位仿真（可选）

如果要检查“同一个点反复到达”的软件流程，使用 `endpoint_repeatability_sim`。它只使用模拟 K0-K4 反馈，不连接 Nano、不打开实体串口、不访问 D405，也不会生成电机命令。

先准备点位文件。每行一个点，坐标单位是米，姿态单位是弧度：

```csv
point_id,target_x_m,target_y_m,target_z_m,target_rx_rad,target_ry_rad,target_rz_rad
left_15,-0.0600460185,0.224094792,0.79,0,0,0
right_15,0.0600460185,0.224094792,0.79,0,0,0
```

运行示例（每点 3 次）：

```bash
mkdir -p /tmp/s3-user-results
build/s3-user/endpoint_repeatability_sim \
  --points tests/fixtures/endpoint_positioning/repeatability_points.csv \
  --collision-config config/enclosure-collision.csv \
  --repetitions 3 \
  --random-seed 20260827 \
  --json /tmp/s3-user-results/repeatability-report.json \
  --csv /tmp/s3-user-results/repeatability-table.csv
```

`--repetitions` 可以设置为 1 到 100，例如 `--repetitions 5` 表示每个点测试 5 次。每次循环是“到达目标 -> 等待稳定 -> 读取模拟反馈 -> 在目标周围 BASE_XY 平面随机退开 15 mm -> 下一次返回目标”。所有点完成后，程序返回模拟安全起点。

返回码仍然是：`0` 全部完成，`1` 预检/超时/反馈/误差失败并停止，`2` 参数或 CSV 格式错误。JSON 会记录每点的重复次数、位置误差、重复性统计、退开角度和路径预检；CSV 会记录每次样本一行。

这是软件流程验证，不是实体定位精度验证。仿真 `PASS` 不能说明真实机械臂能达到 1 mm；真实测试必须另行进行硬件预检和实体测量。

## 9. 常见错误

### 找不到碰撞配置

确认仍在项目根目录，并执行：

```bash
pwd
ls -l config/enclosure-collision.csv
```

不要用空碰撞配置继续运行。

### 找不到输入文件

执行 `ls -l` 检查路径。相对路径必须从 `/home/zzq/PTR/therapy_robot` 执行；不确定时使用绝对路径。

### CSV 表头或列数错误

从 `tests/fixtures/endpoint_positioning/offline_measurements.csv` 复制表头，只改数据行，不要改列名和顺序。

### 只有一侧通过

先看 `reason`。左右结果可能因机箱碰撞、目标姿态和软限位不同而不同；不要仅凭左右数量判断程序错误。

## 10. 结束和安全收尾

临时结果可保留用于调试，也可删除：

```bash
rm -rf /tmp/s3-user-results
```

不要删除或修改以下正式文件：

```text
config/enclosure-collision.csv
tests/fixtures/endpoint_positioning/offline_measurements.csv
tests/test_endpoint_reachability_matrix.cpp
tools/endpoint_positioning_report.cpp
```

完成本流程得到的是软件层结论：哪些点在当前几何模型中可达、哪些点会碰撞、哪些点超出 IK 工作空间、误差是否满足 1 mm/1°。这不是实体运动许可；连接 Nano 或控制机械臂必须另行执行硬件预检并取得明确授权。
